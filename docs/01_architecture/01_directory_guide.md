# Reliability IQ — Folder Purpose Guide

> This document describes the purpose of each top-level directory.
> The authoritative project structure is defined in `docs/01_architecture/01_project_structure.md`.

---

## artifacts/

Immutable outputs generated by pipelines or training runs
(models, serialized objects, intermediate assets).
Nothing in this directory is hand-edited.

---

## data/

Local data storage only. Raw source data is never committed.

- **raw/**
  Original datasets exactly as downloaded from the source.

- **processed/**
  Cleaned, transformed, and feature-ready datasets produced by ingestion pipelines.

---

## docker/

Container definitions and supporting files for local and deployment environments.
Used to ensure consistent runtime behavior across contributors.

---

## docs/

Authoritative project documentation. This is where decisions live.

- **00_overview/**
  Project context, goals, and scope.

- **01_architecture/**
  System design and structure. This is the single source of truth for repository layout.

- **02_data_sources**
  Dataset definitions, provenance, licensing, and access instructions.

- **03_notebooks**
  Notebook conventions and analytical workflow documentation.

- **04_reports**
  Written analytical summaries and findings.

- **05_powerbi**
  Power BI models, dashboards, and exports.

- **06_database**
  Database schemas, design notes, and migration considerations.

- **07_models**
  Model design rationale and evaluation methodology.

- **08_deployment**
  Deployment strategy and environment notes.

- **09_security**
  Security assumptions, risks, and mitigations.

- **10_operations**
  Operational workflows, monitoring concepts, and runbooks.

- **11_project_diary**
  Chronological record of design decisions and project milestones.

- **12_future_plans**
  Planned extensions and deferred ideas.

- **13_lessons_learned**
  Retrospectives and technical takeaways.

- **14_risk_scoring**
  Risk and prioritization framework documentation.

- **15_medium_blog**
  Long-form writeups prepared for external publishing.

---

## figures/

Static images used in documentation, reports, and presentations.
No autogenerated plots are stored here.

---

## logs/

Runtime logs generated during local runs or experiments.
Ephemeral and excluded from version control.

---

## notebooks/

Exploratory and analytical notebooks following a linear workflow.

- **00_baseline.ipynb** — Baseline assumptions and sanity checks
- **01_eda.ipynb** — Exploratory data analysis
- **02_feature_engineering.ipynb** — Feature construction and validation
- **03_modeling.ipynb** — Model development
- **04_evaluation.ipynb** — Model evaluation and comparison
- **05_conclusion.ipynb** — Findings and next steps

Notebooks inform the system; they are not the system.

---

## results/

Final outputs produced by models and analyses
(tables, metrics, exports). Treated as read-only once generated.

---

## src/reliability_iq/

Production source code for the Reliability IQ system.

- **api/**
  API layer and request handling

- **config/**
  Configuration management

- **core**
  Core business logic and workflows

- **db**
  Database access and persistence logic

- **models**
  Model loading and inference code

- **schemas**
  Data contracts and validation schemas

- **services**
  Application services and orchestration

- **static**
  Static assets for web interfaces

- **templates**
  HTML or templated views

- **utils**
  Shared utilities and helpers

- **visualization**
  Visualization logic used outside notebooks

---

## tests/

Automated tests covering core logic, services, and data contracts.
